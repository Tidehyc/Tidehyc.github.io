REDIS / GO-REDIS

连接池在重新认证完成的瞬间，误报「池已耗尽」

问题连接池上限 MaxActiveConns 设为 1 时，一条连接刚完成重新认证、明明已经空闲，紧接着发出的命令却会报 connection pool exhausted。用复现脚本在未修复的代码上跑，-race 下 1,000 次里约 51 次中招。

定位getConn 先用 popIdle 扫一遍空闲连接，此时正在重新认证的连接处于 InUse 状态、被跳过；等流程走到后面的容量检查时，连接其实已经回到 Idle，但容量检查只认还标着 Unusable / InUse 的连接，于是误判池已满，转去拨号又撞上硬上限。

修法在容量上限处、走拨号和报错之前，对空闲列表做一次性重查：若已有连接变得可获取，就重试领取。只查一次、不新增任何等待，PoolTimeout 预算与 TryGet 的非阻塞语义保持不变。回归测试也随之加强成 200 次快速轮换凭据加并发 PING，未修复时稳定失败。

GO-TASK / TASK

离线模式下，标了 optional 的远程 include 没缓存就直接报错退出

问题Taskfile 里把远程 include 标成 optional: true，本意是「本地没有就跳过」；但在 --offline 且缓存不存在时，程序并不跳过，而是报缓存未找到的错误、以退出码 106 结束。

定位include.Optional 只在构造节点的 NewNode 里被检查，而远程文件的离线缓存查找发生在更晚的 Node.Read() 阶段——检查点和真正出错的位置错开了，optional 的语义在离线路径上根本没生效。

修法在 reader.go 的 include() 里把检查前移：往图里加节点之前，先试读一次本地缓存；optional + 离线 + 远程节点且缓存不存在时直接跳过。同时保证嵌套的非 optional 远程 include 的缓存错误不会被外层 optional 父级吞掉，并补了覆盖直接与嵌套 optional 组合的单元测试。

UBER / KRAKEN

四个被跳过了六年的 TLS 测试

问题utils/httputil 里的四个 TLS 客户端测试自 2019 年起一直被 skip 掉，年年躺在代码库里，没人知道它们到底还能不能过。

定位把 skip 摘掉后，暴露出两个互不相干的失败：一是测试生成的证书只填了 CommonName、没有 SAN，Go 1.15 起 x509 校验直接拒绝这种证书；二是 2022 年的一次改动把 HTTP 回退改成了需要显式开启（EnableHTTPFallback），而被跳过的测试从没跟上这个变化。

修法给测试证书模板补上 DNSNames；回退测试显式开启 EnableHTTPFallback()；顺手把测试服务器的监听地址改绑 127.0.0.1:0，不再占用通配地址。纯测试改动，本地用 -count=20 -race 反复跑过验证。
